# Spec changes

Every change to `SPEC.md`, with the reason. Newest first.

Recording rule: a spec change that exists because the implementation drifted is the metric
we call spec drift, not a fix. Write it down as drift.

| Date | Feature | Spec version | What changed | Why | Drift? |
|---|---|---|---|---|---|
| 2026-11-02 | C6, section 3, section 4, section 5, B1, R3, I2, F2.AC2, F4.AC6 | 1.0-draft | a second kind of sensor: Zigbee sensors published by Zigbee2MQTT on the same broker, configured as `{ zigbee: <name> }`, with the optional `mqtt.zigbee2mqtt_topic`. Every reading is taken in °C (`tC`, or `temperature`) and converted to °F with unit `F`; `tF` is ignored. **Replaces** "never converts" and readings from `tF`, from the unit row below. The section 4 example now has one Zigbee sensor in each room, in place of the Add-on probe and the second H&T. F2.AC2 covers both kinds; F4.AC6 gives its readings in °C | author: the house's sensors are a Shelly H&T Gen3 and two Shelly BLU H&T Display ZB, which speak Zigbee and Bluetooth, not MQTT, and reach the broker through Zigbee2MQTT on the existing Home Assistant server. They report °C only. Before the freeze, so no version bump | no |
| 2026-11-02 | section 3, section 4, section 5, B1, R3, L1, F4 | 1.0-draft | new required key `unit`, `C` or `F`; every temperature `heatctl` reads, decides on, shows or logs is in it, with no conversion. With `F`: readings from `tF`, default `hysteresis` 1.0, targets 45.0 to 77.0. L1 gains a `unit` field. New criterion F4.AC6; the other criteria use unit `C` | author: the house may be set up in either unit. Before the freeze and before any event was written, so no version bump and `schema` stays 1 | no |
| 2026-11-02 | F5 | 1.0-draft | new criterion F5.AC6: the broker goes away while a relay is on, and the relay is off within `relay_lease` | B9 already covered losing the broker, but no criterion did. A relay turned off only by the broker's last will passes F5.AC3 and stays on for good when the broker itself is gone. Before the freeze, so no version bump | no |
| 2026-11-02 | R4, B6, F6.AC3, F6.AC6 | 1.0-draft | **reverses the R4 row below:** no control cycle runs during `startup_grace`, so no L1 event is written; B6 says cycles run once the start is over. F6.AC3 says no cycle runs; F6.AC6 is back to "after the first control cycle" | author, on second thought. Before the freeze, so no version bump | no |
| 2026-11-02 | B9, F5 | 1.0-draft | while `heatctl` runs and reaches the broker, a relay that should be on never turns itself off between two commands. New criterion F5.AC5 | without it, a build could let a relay lapse and turn it back on only when the mismatch is noticed (B8), cutting the boiler for about 30 s every 15 minutes. Before the freeze, so no version bump | no |
| 2026-11-02 | I1 | 1.0-draft | nothing `heatctl` publishes is retained, its last will included | a retained `on,<seconds>` would turn a relay back on when the device reconnects after `heatctl` has gone, which defeats B9. Before the freeze, so no version bump | no |
| 2026-11-02 | section 4 | 1.0-draft | `switch` and `component` are integers, 0 or more | author: the values a channel id takes were unsaid. Before the freeze, so no version bump | no |
| 2026-11-02 | section 4 | 1.0-draft | targets between 7.0 and 25.0 inclusive, was 5.0 to 30.0 with no word on the ends. Temperatures may be written without decimals. Every schedule entry has a `from` and a `target` | author, on gaps found while writing the expectations. Before the freeze, so no version bump | no |
| 2026-11-02 | R4, F6.AC3, F6.AC6 | 1.0-draft | control cycles run and are logged during `startup_grace`, but send no relay command; the first cycle after it commands every relay to its desired state. F6.AC3 says the cycles run; F6.AC6 reads "once the room has reported" instead of "after the first control cycle", which now comes during the grace | author: B6 ran a cycle on every reading while R4 put the first cycle after the grace. Before the freeze, so no version bump | no |
| 2026-10-31 | section 4, B4, F4 | 1.0-draft | default `hysteresis` 0.3 → 0.5 °C, either side of the target. F4.AC1 reading 19.6 → 19.4; F4.AC2 readings 20.2 and 20.3 → 20.4 and 20.5 | author: 0.5 is the common thermostat default. Before the freeze, so no version bump | no |
